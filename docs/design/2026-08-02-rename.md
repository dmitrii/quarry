# Design: `quarry rename`

Status: approved for planning · Date: 2026-08-02

## Problem

A year of sessions are unnamed (they list by UUID). Setting a title today means
resuming each session and running `/rename` interactively. We want to title
sessions in bulk (and single sessions quickly) from outside a session, with an
LLM proposing each title, under the user's own naming convention — nothing about
the format baked into the tool.

## How titles persist (established by investigation)

`/rename` appends one record to the session's own transcript:

```json
{"type":"custom-title","customTitle":"my-title","sessionId":"<uuid>"}
```

The title lives **only** there — not in `~/.claude.json`, not in `history.jsonl`.
The reader takes the **last** `custom-title` in the file, and (per an Anthropic
issue and the `claude-agent-sdk` source) the session list scans only the file
**tail** (~64 KB), so a title must sit near the end to be seen. This is exactly
what we will do — append at EOF. No central file is ever rewritten.

We deliberately take **no new dependency**: both applying the title and
generating the summary are done with tools already present (`claude` CLI).

## CLI

```
quarry rename [selector] [-t/--template TMPL] [--retitle] [-n/--dry-run]
              [--model M] [--color {auto,always,never}]
```

- **selector** (optional, positional): a shell-style glob (`*`, `?`) matched
  against each session's UUID **or** current name.
  - **omitted** → the last session run in `$PWD` (same resolution as `quarry rm`
    with no argument). Solves the "leave the session, type `quarry rename`" case.
  - given → the matched set.
- **template** is always a flag (`-t`), never positional — this removes the
  two-optional-positionals ambiguity. Defaults to the config `default_template`.
- **`--retitle`**: include sessions that already have a custom title.
- **`-n/--dry-run`**: print the matched sessions and their rendered template
  *skeleton* (all free variables incl. `$AI_TITLE` and fallbacks resolved,
  `$SUMMARY` left literal) — no model calls, no writes. A cheap "what would run /
  how many match" preview.
- **`--model`**: convenience override passed to the default summary command.

### Selection semantics

- Already-titled sessions are **skipped** unless `--retitle`, **except** when the
  selector resolves to a single explicitly-named target (a bare UUID/prefix, or
  the no-argument last-session default) — those are always offered, with the
  current title shown in the confirm step.
- Subagent sidechains are never candidates (they are already hidden from `ls`).
- Sessions currently open in a live process are refused (as in `quarry rm`).
- The run is **re-runnable**: because titled sessions are skipped by default, a
  `Ctrl-C`'d batch can be rerun and picks up where it left off.

## Template and variables

The template is a string with `$VAR` placeholders (bare `$VAR` or braced
`${VAR}`). After substitution the title is normalized **minimally**: surrounding
quotes/whitespace stripped, internal whitespace → `-`, and **empty/duplicate
separators collapsed** so a blank `$GIT_PROJECT` never leaves
`2026-08-02--fix-thing`. Case is left as produced (the default `$SUMMARY` prompt
already yields lowercase) — quarry does not force a case convention.

**Fallback:** `${VAR:-fallback}` yields `fallback` when `VAR` renders empty (shell
`:-` semantics). `fallback` is itself a rendered fragment, so it can be literal
text or another variable — e.g. `${AI_TITLE:-$SUMMARY}` means "reuse the free AI
title, otherwise generate one."

**Lazy generation:** `$SUMMARY` runs the generator only when a `$SUMMARY` token is
actually reached during rendering. So `${AI_TITLE:-$SUMMARY}` incurs **no** model
call for the ~23% of sessions that already have an AI title.

**Free / offline / deterministic** (no model call):

| Variable | Value |
|---|---|
| `$START_DATE` | session start date, local tz, `YYYY-MM-DD` |
| `$LAST_ACTIVITY_DATE` | last-activity date, local tz, `YYYY-MM-DD` |
| `$LAUNCH_DIR` | basename of the session's launch directory |
| `$GIT_PROJECT` | basename of the enclosing `.git` root, else empty |
| `$BRANCH` | git branch recorded in the log, else empty |
| `$UUID` / `$UUID8` | full / first-8 of the session UUID |
| `$AI_TITLE` | kebab-cased auto-generated AI title (`ai-title` record); empty when absent (~23% of sessions have one) |

**Model-derived** (the only variable that triggers a generator call):

| Variable | Value |
|---|---|
| `$SUMMARY` | a 3–8 word lowercase kebab slug describing the session |

A template using only free variables (e.g. `$START_DATE-$GIT_PROJECT`) renames
instantly with zero cost and zero network.

## `$SUMMARY` generation — pluggable generator

**Contract:** quarry pipes the session **context to the command's stdin**; the
command prints the **title to stdout**. That is the whole interface — any command
honoring it can be dropped in (different model, local LLM, etc.). Because context
travels on stdin, `ARG_MAX` is irrelevant; context size is bounded only by cost.

**Shipped default `summary_command`** (lives in code as the authoritative default;
`make install-config` mirrors it into `config.ini` for editing):

```
claude -p --no-session-persistence --model haiku --effort low --tools "" \
  --system-prompt "You output ONLY a 3-8 word lowercase kebab-case slug \
summarizing the session topic. Do not include the project, repo, or tool name. \
No dates, no quotes, no punctuation, no explanation."
```

- `--no-session-persistence` — verified to leave **no** transcript on disk (no
  `quarry ls` pollution); reuses the existing Claude Code subscription auth (no
  API key). `--effort low` and `--tools ""` keep it cheap and side-effect-free.
- The instruction (including "do not include the project/repo/tool name") lives
  in the command string, so the wording is the user's to edit.

**Context** = all user prompts, in order, via the existing
`scan_text(path, replies=False)`, truncated to `summary_context_chars` (default
8000, head-kept). Bash-mode inputs are intentionally left in — they can be
relevant to naming.

**Execution:** run via `subprocess.run(..., input=context, timeout=...)` (Python's
own timeout — no `timeout(1)` binary needed). The rendered stdout is stripped and
normalized. On non-zero exit / timeout / empty output: warn and fall back to a
manual title entry for that session (never abort the whole batch).

## Apply — defensive tail-append

`set_custom_title(session, title)`:

1. Validate: UUID well-formed; title non-empty after strip; session not currently
   open (refuse otherwise).
2. Ensure the file ends in a newline, then append
   `{"type":"custom-title","customTitle":<title>,"sessionId":<uuid>}\n`.
3. **Read back** with our own parser and assert the title now resolves; if not,
   raise a clear error ("quarry's understanding of the transcript format may be
   out of date"). This is the fail-fast guard against format drift.

## Per-item confirm UX

For each matched session, in order:

1. Print the `quarry ls <uuid>` detail view (full context to decide on a name).
2. Generate `$SUMMARY` if the template needs it (a brief "generating…" note; the
   detail above masks the latency).
3. Present the proposed title in an **editable readline field** (prefilled):
   - **Enter** → apply the shown/edited title.
   - **empty line** (clear with Ctrl-U, then Enter) → skip this session.
   - **Ctrl-C** → abort the batch.

Portability note: macOS Python uses libedit, so we rely only on prefill + native
line editing (no custom key bindings). ESC-to-skip would need raw-terminal mode
and is intentionally not used.

## Config (`[rename]` in `~/.config/quarry/config.ini`)

| Key | Default |
|---|---|
| `default_template` | `${AI_TITLE:-$SUMMARY}` (reuse the free AI title, else generate) |
| `summary_command` | the `claude -p …` command above |
| `summary_context_chars` | `8000` |
| `summary_timeout_secs` | `60` |

Defaults are authoritative in code (quarry works with no config file).
`config.ini.example` mirrors them; a unit test asserts the two match so they can't
drift.

## Components

- **`src/cmd_rename.py`** (new): argument parsing, selection, the interactive
  per-item loop, `--dry-run`.
- **`src/claude_sessions.py`** (additions): `RenameConfig` + `load_rename_config`;
  `render_template`; per-variable resolvers incl. `git_project(cwd)`;
  `generate_summary`; `set_custom_title`.
- **`bin/quarry`**: register the `rename` subcommand; add it to completions.

## Error handling

- No sessions match → friendly message, exit non-error.
- Session open → refuse that session, continue with the rest.
- Generator failure/timeout → warn, fall back to manual entry for that session.
- Apply read-back mismatch → clear, actionable error; stop that item.

## Testing

- Template rendering: variables, empty-segment collapse, normalization.
- `git_project` detection (with/without `.git`).
- `generate_summary` plumbing using a **real deterministic** `summary_command`
  (e.g. a tiny shell filter), not a mock, to verify stdin→stdout + truncation +
  timeout handling.
- `set_custom_title`: append + read-back; UUID guard; non-empty guard; refuse
  when open.
- Selection: glob, last-session default, skip-titled vs `--retitle`.
- Config parsing + the code/`config.ini.example` sync assertion.
- Interactive loop is exercised at the seams (selection, generation, apply);
  keystroke handling is kept thin.

## Out of scope (future)

- Searching / titling from `tool_use` (commands) or `tool_result` (output) — far
  larger; would need a persistent index.
- Caching generated summaries; parallel prefetch of the next session's summary.
- Full-transcript context via `--resume` (blows the context window on large
  sessions; the condensed user-prompt context is the scalable choice).

## Dependencies

None new. Uses the already-present `claude` CLI for generation and stdlib for
everything else.
